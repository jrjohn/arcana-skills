# 證據:2026-07-30 的量測與三個假紅

> 這份檔案存在的理由:`SKILL.md` 的每一條規則都必須指得出「哪件事讓我們知道它是真的」。
> 沒有這份檔案,那些規則就只是品味。

系統:`sdlc-code-flow` —— 一條 BPMN 驅動的 SDLC 流水線,AI 節點負責 IntakeReview / SA / SD /
UI-UX / implement / test / PM 判定。同一個能力(查這個產品自己的對話歷史)用兩種措辭提供,
量三輪。

## 1. 主量測:許可句 vs 命令句

同一個能力、同一批節點,逐 `tool_use` 計數(**寫在回答裡說「我會查」不算**,那跟把 skip
掉的閘讀成通過是同一個錯誤)。

| 節點 | 收到什麼 | 輪 A `b8ed3c85` | 輪 B `e9c6b692` | 輪 C `e7dfd560` |
|---|---|---|---|---|
| IntakeReview | 輪 B 只有我需求散文裡**一句命令句**;輪 C 有命令句 brief + 工作區 CLAUDE.md | 0 | **15** | **15** |
| SA | 輪 C 起**只有工作區 CLAUDE.md** | 0 | 0 | **2** |
| SD | 同上 | 0 | 0 | **2** |
| implement | 輪 B 是 783 字**許可式**注入;輪 C 改命令句 | 0 | **0** | **5** |
| pmReview | 同上 | 0 | **0** | **4** |
| journey / testcases | 只有工作區 CLAUDE.md | 0 | 0 | 0 |
| **合計** | | **0** | **15** | **28** |

### 下結論前先排除的解釋

- **指引沒送到?** 不是。輪 B 當下驗過:函式在執行中的映像裡、接在 prompt 上、用該實例
  自己的 payload 呼叫回傳 783 字。**送到了而沒被採用。**
- **記憶沒開?** 輪 B 開著 —— per-product db 37MB / 7,005 則,ingest 全程在跑。
- **輪 C 是因為我在需求裡叫它查?** 不是。輪 C 的需求本文**沒有一個字**提到記憶、歷史或
  查詢;只提到 `#94/#95` 與一個缺陷編號,那是**觸發條件**,不是指令。

### 為什麼

> **一個被標示為可選的能力,每次都輸給眼前的任務。** 節點手上永遠有一件具體的大工作
> (寫程式、編譯、開 PR)。

而指引還多說了一句「不是每次都要」—— **那句本身就是跳過的授權**。

### SA / SD 是乾淨對照

它們**只**拿到工作區 CLAUDE.md,沒有程式注入的 brief。前兩輪共 4 個 session、查詢 0;
輪 C 只多了一個檔案,兩者各查 2 次。這回答了「每個工作區節點的 CLAUDE.md 都加指引有沒有用」。

`journey` / `testcases` 仍是 0 —— **這是誠實的結果**,不是失敗:它們從規格生成產物,
手上沒有「這件事以前做過嗎」這個問題。CLAUDE.md 不是讓每個節點都去查,是讓有理由查的去查。

## 2. 措辭之外的效果:它查到了什麼

次數只是代理指標。實際發生的事:

1. **IntakeReview 推翻了需求的前提。** 需求說「組織圖節點互相遮蔽」,它查出 `/org` 那 222 筆
   重疊的主體是收合 `<details>` 面板與側欄卡片,只有 3 筆與 `org-box` 有關且都是 minor。
   照原需求做,數字會掉到 219、AC「< 222」通過、畫面幾乎沒變 —— **一個空過的綠燈**。
2. **它查出 `/org` 桌面版從來沒被那個閘量過**:唯一量得到的斷點是 375×740 手機單欄,
   另兩個被重導去 `/login`。閘一直在量一個沒人用的版面並給綠。
3. **SD 用 vsearch 直接查那個重導的成因**,而不是從零推測。

兩件都在寫任何一行規格之前發生。

## 3. 三個假紅,同一個家族

同一天在同一套系統上抓到三個,而它們是同一個錯誤:**檢查回答了一個比較容易問的問題**。

| 假紅 | 它問的 | 該問的 | 後果 |
|---|---|---|---|
| `upstream_refusal()` | `INPUT_INCOMPLETE` 這個詞出現過嗎 | 這是一份拒絕嗎 | 一份 16.5KB 的健康設計,因為寫了「輸入充足,**不需** INPUT_INCOMPLETE」而讓下一棒停工 |
| 測試案例 `FEAT-03` | `GET /api/v1/org` 回 200 嗎 | (真端點是 `/api/v1/org/nodes`) | 一條無論怎麼實作都過不了的 AC |
| runner 新鮮度守衛 | 這個檔案存在嗎 | image 是不是從這個 PR 建的 | 五個被 PR 修改的閘檔案,image 跑舊版而不出聲 |

**假紅跟假綠一樣貴。** 有一點還更貴:假綠會被人審,而停掉的流程會被重跑 —— 然後撞同一面牆。

修法都一樣:把判準從「字串在不在」換成「這是不是一個宣告」。
`upstream_refusal` 改成行首比對;守衛改成 `sha256` 逐位元。

> Existence is the wrong question. The question is whether the bytes match.
> —— implement 節點自己在修好的守衛裡寫的註解

## 4. 五個靜默缺席的能力

每一個都是「compose 裡宣告了、runtime 不存在、而不存在跟正常運作長得一模一樣」。

| 能力 | 缺的變數 | 怎麼靜默失敗 |
|---|---|---|
| 經理留言 | `RBAC_SVC_USER` | 回空清單 |
| 逐字稿進 archive | `ARCHIVE_PG` | 函式第一行就 return |
| RBAC UI 閘 | `RBACUI_ACTORS` | 每次 skip,卻貢獻 `rbac_fail=0` 的免費綠 |
| per-product 記憶 | `PROJECT_MEMORY` | brief 變空字串,沒有節點被告知 |
| 產品身分 | payload 少一個 `repo` | `_project_slug()` 回 ""、四道閘第一道就關,無 log |

第四個當天實際發生:`PROJECT_MEMORY=1` 被 inline 帶在 `docker compose up` 命令列,
`--force-recreate` 一跑就掉回預設 `0`。**白燒一輪量測才 `printenv` 抓到。**

**推論**:掉了會立刻爆的變數(token)反而安全;掉了系統照跑的變數(功能旗標)才危險 ——
因為沒有人會發現。所以判準是:**凡是「關掉之後系統仍正常運作」的東西,都必須寫進持久設定,
並在啟動時把狀態印出來。**

## 5. 這份檢查器自己抓到的第一個缺陷

`--selftest` 第一次跑,11 條有 4 條 fire 不起來 —— 而另外 7 條「✅」是**空過的**
(什麼都沒 fire,當然不誤報)。真因是 `resolve_paths()` 在 pipe 裡寫了 `local f="$1"`,
`set -u` 把整條管線炸掉。

修好之後,它對**作者自己當天產出的**工作區 CLAUDE.md 報了 `no-consequence` —— 那份檔案
從頭到尾沒說「不查會怎樣」。處置是**改文件,不是放寬檢查**。

這兩件是這個工具唯一的信用來源:**它抓過寫它的人。**
